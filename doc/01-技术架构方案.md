# Nexus Studio 技术架构方案

## 1. 项目概述

Nexus Studio 是一款基于 Electron 的跨平台桌面数据库客户端工具，首期目标为提供完善的 PostgreSQL 数据库管理能力，后续将逐步扩展 AI 智能辅助功能（如自然语言转 SQL、智能查询优化、数据分析建议等）。

### 1.1 技术定位

- **类型**: 跨平台桌面应用（Windows / macOS / Linux）
- **架构模式**: Electron 三层架构（主进程 / 预加载进程 / 渲染进程）
- **开发语言**: TypeScript（全栈统一类型安全）
- **UI 范式**: 类 IDE 布局，多标签页、多面板、可拖拽

## 4. 核心模块设计

### 4.1 数据库连接层

采用**适配器模式**设计，为后续多数据库支持预留扩展点：

```typescript
// 数据库适配器接口
interface IDatabaseAdapter {
  // 连接管理
  connect(config: ConnectionConfig): Promise<void>;
  disconnect(): Promise<void>;

  // 查询执行
  execute(sql: string, params?: unknown[]): Promise<QueryResult>;
  executeMultiple(queries: string[]): Promise<QueryResult[]>;
  cancelQuery(): Promise<void>;

  // Schema 浏览
  getDatabases(): Promise<Database[]>;

  getIndexes(table: string, schema: string): Promise<Index[]>;

  // 数据导入导出
  exportData(sql: string, format: ExportFormat): Promise<Buffer>;
  importData(table: string, data: Buffer, format: ImportFormat): Promise<ImportResult>;
}

// PostgreSQL 适配器实现
class PostgreSQLAdapter implements IDatabaseAdapter { ... }
```

### 4.2 连接池管理

### 4.3 IPC 通信设计

基于 Electron 的 `contextBridge` + `ipcRenderer/ipcMain` 实现进程间通信，遵循**请求-响应**模式：

```
渲染进程 ──(invoke)──> 预加载进程 ──(ipcRenderer.invoke)──> 主进程
渲染进程 <──(result)── 预加载进程 <──(ipcMain.handle)─────── 主进程
```

**IPC 通道设计**：

| 通道名               | 方向            | 功能                   |
| -------------------- | --------------- | ---------------------- |
| `db:connect`         | Renderer → Main | 建立数据库连接         |
| `db:disconnect`      | Renderer → Main | 断开数据库连接         |
| `db:test-connection` | Renderer → Main | 测试连接               |
| `db:execute`         | Renderer → Main | 执行 SQL 查询          |
| `db:cancel`          | Renderer → Main | 取消正在执行的查询     |
| `db:get-schemas`     | Renderer → Main | 获取 Schema 列表       |
| `db:get-tables`      | Renderer → Main | 获取表列表             |
| `db:get-columns`     | Renderer → Main | 获取列信息             |
| `file:export`        | Renderer → Main | 导出数据到文件         |
| `file:import`        | Renderer → Main | 从文件导入数据         |
| `file:save`          | Renderer → Main | 保存 SQL 文件          |
| `file:open`          | Renderer → Main | 打开 SQL 文件          |
| `ai:chat`            | Renderer → Main | AI 对话（预留）        |
| `ai:generate-sql`    | Renderer → Main | 自然语言转 SQL（预留） |

## 5. 数据流设计

### 5.1 SQL 查询执行流程

```
用户输入 SQL → 点击执行
    │
    ▼
SqlEditor 组件 ──(setLoading)──> queryStore
    │
    ▼
queryService.execute(sql, connectionId)
    │
    ▼
window.electronAPI.db.execute(sql, params)
    │
    ▼  (IPC)
ipcMain.handle('db:execute')
    │
    ▼
PostgreSQLAdapter.execute(sql, params)
    │
    ▼
pg.Pool.query(sql, params)
    │
    ▼
返回 QueryResult ──(IPC)──> 渲染进程 ──> queryStore.setResult()
    │
    ▼
ResultTable 组件重新渲染
```

### 5.2 连接管理流程

```
ConnectionDialog 表单提交
    │
    ▼
connectionService.connect(config)
    │
    ▼
window.electronAPI.db.connect(config)
    │
    ▼  (IPC)
ConnectionManager.createConnection(config)
    │
    ▼
PostgreSQLAdapter.connect(config) ──> new pg.Pool(config)
    │
    ▼
连接成功 → 返回 connectionId
    │
    ▼
connectionStore.addConnection() + setActiveConnection()
    │
    ▼
SchemaTree 自动加载该连接的数据库结构
```

## 6. 安全设计

### 6.1 进程隔离

- 数据库驱动仅在主进程运行，渲染进程不直接访问 Node.js API
- 通过 `contextBridge` 暴露有限且安全的 API 集合
- 启用 `contextIsolation: true` 和 `nodeIntegration: false`

### 6.2 凭据安全

- 连接密码使用 Electron `safeStorage` API 加密存储
- 敏感信息不记录到日志文件
- 支持操作系统密钥链（macOS Keychain / Windows Credential Manager）

### 6.3 SQL 注入防护

- 使用参数化查询（`$1, $2, ...`）替代字符串拼接
- 对用户输入 SQL 进行语法校验和危险操作警告（DROP, TRUNCATE 等）

## 7. 性能优化策略

| 策略          | 说明                                                    |
| ------------- | ------------------------------------------------------- |
| 虚拟滚动      | 大数据集结果展示使用 `@tanstack/react-virtual` 虚拟滚动 |
| 查询分页      | 大结果集分页加载，默认每页 100 条                       |
| 连接池复用    | 使用 `pg.Pool` 连接池，避免频繁创建/销毁连接            |
| 懒加载 Schema | 按需展开 Schema 树节点，避免一次性加载所有元数据        |
| SQL 编辑器    | Monaco Editor 按需加载 Web Worker                       |
| 查询取消      | 支持取消长时间运行的查询，释放数据库资源                |
| Debounce      | 搜索/筛选操作使用 debounce 减少不必要的请求             |
