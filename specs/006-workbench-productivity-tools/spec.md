# Feature Specification: 工作台效率工具集（导出/DDL/格式化/复制/导入）

**Feature Branch**: `006-workbench-productivity-tools`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "实现所有任务：

- 导出查询结果 — 表格右键"导出为 CSV/JSON"，现在只能通过定时任务间接导出，太绕了
- 查看 DDL — SHOW CREATE TABLE / SHOW CREATE VIEW，右键表名就能看到 DDL，这是最常用的
- SQL 格式化 — 编辑器里一键美化 SQL，没有很痛苦
- 复制行数据 — 选中行 → 复制为 INSERT / 复制为 JSON / 复制为 CSV，调试时频繁用
- 数据导入 — 导入 CSV/JSON/SQL 文件到表，不支持"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 查看表 / 视图的 DDL（Priority: P1）

用户在数据库导航树中右键点击某张表或视图，直接看到该对象的完整建表/建视图语句（DDL），无需手动拼接 `SHOW CREATE TABLE` 等语句并单独执行查询。

**Why this priority**: 用户明确指出这是"最常用"的操作。当前完全不支持，用户只能自己手写并执行 `SHOW CREATE TABLE`/`SHOW CREATE VIEW`，每次都要中断当前工作去切换到查询窗口。这是路径最短、价值最高的单点改进。

**Independent Test**: 在导航树中右键任意一张表，选择"查看 DDL"，验证弹出的内容与手动执行 `SHOW CREATE TABLE` 得到的结果一致；对视图重复同样的验证，使用 `SHOW CREATE VIEW`。该功能不依赖本规格中的其他功能即可独立交付和验证。

**Acceptance Scenarios**:

1. **Given** 已连接的数据库连接下存在一张表，**When** 用户在导航树中右键该表并选择"查看 DDL"，**Then** 系统展示该表完整的建表语句（包含列定义、约束、索引）。
2. **Given** 已连接的数据库连接下存在一个视图，**When** 用户在导航树中右键该视图并选择"查看 DDL"，**Then** 系统展示该视图的完整定义语句。
3. **Given** DDL 已展示，**When** 用户点击复制按钮，**Then** 完整 DDL 文本被复制到系统剪贴板。
4. **Given** 用户对该表没有查看定义所需的权限，**When** 用户请求查看 DDL，**Then** 系统展示明确的错误提示而不是空白或崩溃。

---

### User Story 2 - 导出查询结果为 CSV / JSON（Priority: P2）

用户在查询结果表格中右键，直接选择"导出为 CSV"或"导出为 JSON"，将当前查询结果保存为本地文件，无需先创建一个定时任务再间接导出。

**Why this priority**: 用户明确指出当前的间接导出路径"太绕了"，是高频痛点。仅次于 DDL 查看，属于第二高价值的独立可交付能力。

**Independent Test**: 执行一条返回若干行的查询，在结果表格中右键选择"导出为 CSV"，验证生成的文件行数、列数、内容与查询结果一致；对"导出为 JSON"重复验证。该功能不依赖导入、复制、格式化等其他功能。

**Acceptance Scenarios**:

1. **Given** 查询已成功执行并显示结果，**When** 用户在结果表格上右键并选择"导出为 CSV"，**Then** 系统提示选择保存位置，并生成一个包含全部结果行、以表头为首行的 CSV 文件。
2. **Given** 查询已成功执行并显示结果，**When** 用户选择"导出为 JSON"，**Then** 系统生成一个 JSON 文件，每行结果对应一个 JSON 对象，字段名与结果列名一致。
3. **Given** 结果集中某些单元格为 NULL 或包含逗号、换行、双引号等特殊字符，**When** 导出为 CSV，**Then** 特殊字符被正确转义，NULL 被表示为空值而不是字符串 "null"。
4. **Given** 查询结果为空（0 行），**When** 用户执行导出，**Then** 系统生成只包含表头（CSV）或空数组（JSON）的文件，而不是报错。
5. **Given** 导出正在进行中，**When** 结果集较大，**Then** 系统显示导出进度或至少的"进行中"状态，且不冻结界面。

---

### User Story 3 - 复制选中行为 INSERT / JSON / CSV（Priority: P3）

用户在结果表格中选中一行或多行，右键选择"复制为 INSERT"、"复制为 JSON"或"复制为 CSV"，将所选行以对应格式复制到系统剪贴板，用于调试或粘贴到其他工具。

**Why this priority**: 用户指出这是调试时的高频操作，但相较导出（面向"保存结果"）和 DDL 查看，使用场景更聚焦于即时排查，优先级排第三。

**Independent Test**: 打开一张表的数据浏览视图或一条 SELECT 查询结果，勾选 1 行及多行，分别选择三种复制格式，粘贴到文本编辑器中验证内容格式正确。该功能不依赖导出或导入功能。

**Acceptance Scenarios**:

1. **Given** 结果表格中已勾选一行，**When** 用户右键选择"复制为 JSON"，**Then** 剪贴板内容为该行的 JSON 对象（字段名为列名）。
2. **Given** 结果表格中已勾选多行，**When** 用户选择"复制为 CSV"，**Then** 剪贴板内容为不含表头、以逗号分隔的多行文本，行顺序与表格中显示顺序一致。
3. **Given** 结果来自浏览单一表的数据（表名可确定），**When** 用户选择"复制为 INSERT"，**Then** 剪贴板内容为一条或多条可直接执行的 `INSERT INTO <表名> (...) VALUES (...)` 语句，值按列类型正确加引号/转义。
4. **Given** 结果来自多表关联查询（无法确定唯一来源表），**When** 用户选择"复制为 INSERT"，**Then** 系统仍生成语法正确的 INSERT 语句骨架（使用结果集列名，表名以占位符呈现），并提示用户核对表名后使用。
5. **Given** 用户未勾选任何行，**When** 用户尝试使用"复制为…"菜单项，**Then** 该菜单项不可用或提示"请先选择行"。

---

### User Story 4 - SQL 编辑器一键格式化（Priority: P4）

用户在 SQL 编辑器中编写或粘贴了未格式化的 SQL，通过一个按钮或快捷键一键美化当前 SQL 文本的排版（缩进、换行、关键字大小写等），无需手动调整。

**Why this priority**: 用户形容当前状况是"没有很痛苦"，即改善型需求而非阻断型痛点，因此优先级最低，但仍是本次要交付的能力之一。

**Independent Test**: 在 SQL 编辑器中输入一段单行、无缩进的 SQL，触发格式化操作，验证输出的 SQL 具备统一的换行、缩进和关键字风格，且格式化前后语句在数据库中执行结果一致（不改变语义）。该功能不依赖其他任何用户故事。

**Acceptance Scenarios**:

1. **Given** 编辑器中有一段结构混乱的 SQL 语句，**When** 用户触发"格式化"操作，**Then** 编辑器内容被替换为排版规范的等价 SQL（关键字统一大小写、子句换行、统一缩进）。
2. **Given** 编辑器中包含多条以分号分隔的 SQL 语句，**When** 用户触发格式化，**Then** 每条语句均被独立格式化，语句间的分隔保持不变。
3. **Given** 编辑器中的 SQL 存在语法错误（无法解析），**When** 用户触发格式化，**Then** 系统提示无法格式化并保留原始文本不变，而不是产生损坏的 SQL。
4. **Given** 用户已格式化过一次 SQL，**When** 用户执行撤销操作，**Then** 编辑器恢复到格式化之前的文本。

---

### User Story 5 - 导入 CSV / JSON / SQL 文件到表（Priority: P5）

用户选择一个已存在的目标表，从本地选择一个 CSV、JSON 或 SQL 文件，将文件中的数据导入该表（CSV/JSON 按行映射为记录写入；SQL 文件按语句顺序执行），并在导入完成后看到成功/失败的汇总结果。

**Why this priority**: 用户指出这是当前完全不支持的能力，价值高但涉及的场景最多（三种文件格式、列映射、错误处理），实现和验证成本也最高，因此排在最后交付，但仍是本次范围内的功能。

**Independent Test**: 准备一个与目标表列结构匹配的小型 CSV 文件，执行导入，验证表中新增了对应行且字段值正确；对 JSON 与 SQL 文件重复验证，并验证一份包含错误数据的文件能给出清晰的失败汇总而不会导致部分数据处于不一致状态。该功能不依赖导出、复制或格式化功能。

**Acceptance Scenarios**:

1. **Given** 用户已选择一张已存在的目标表和一个列名与表结构匹配的 CSV 文件，**When** 用户确认导入，**Then** 文件中的每一行被写入该表，导入完成后显示成功写入的行数。
2. **Given** 用户选择的 JSON 文件是一个对象数组，字段名与目标表列名匹配，**When** 用户确认导入，**Then** 每个对象被写入表中对应的一行。
3. **Given** 用户选择的 SQL 文件包含多条语句，**When** 用户确认导入，**Then** 系统按顺序执行这些语句，并在全部完成或首次失败时报告结果。
4. **Given** CSV/JSON 文件中的列名与目标表列名不完全一致，**When** 用户进入导入流程，**Then** 系统提供列映射步骤，让用户将文件中的字段对应到目标表的列，未映射的必填列会被提示。
5. **Given** 导入过程中某一行数据违反了表约束（如唯一性、非空），**When** 该行写入失败，**Then** 系统停止导入并回滚本次导入已写入的数据，同时报告具体失败的行号和原因（不产生部分导入的不一致状态）。
6. **Given** 用户选择的文件为空或格式无法解析，**When** 用户尝试导入，**Then** 系统在写入任何数据前提示文件无效。

---

### Edge Cases

- 导出/导入过程中用户断开数据库连接或关闭应用，会发生什么？系统应中止操作并提示未完成，不留下半成品文件或半写入的数据。
- 表或视图在用户右键查看 DDL 与实际查询之间被删除或重命名，系统应提示对象不存在而不是显示过期的 DDL。
- 导出文件已存在于目标路径时，如何处理（覆盖确认 vs 自动重命名）？
- 复制为 INSERT 时某一列值包含超长文本或二进制内容，如何在生成的语句中表示？
- SQL 格式化面对包含数据库特定方言语法（如存储过程、触发器定义）时，若解析器不支持，应明确报错而不是破坏原文本。
- 导入文件的字符编码非 UTF-8（如 GBK）时如何处理。
- 用户同时选中的行数极多（如数千行）时，"复制为…"操作的响应时间和剪贴板容量限制。

## Requirements _(mandatory)_

### Functional Requirements

**查看 DDL**

- **FR-001**: 系统 MUST 在数据库导航树中为表和视图提供右键菜单项"查看 DDL"。
- **FR-002**: 系统 MUST 能展示表的完整建表语句（列、类型、默认值、约束、索引）。
- **FR-003**: 系统 MUST 能展示视图的完整定义语句。
- **FR-004**: 系统 MUST 提供一键复制 DDL 文本到剪贴板的操作。
- **FR-005**: 当获取 DDL 失败（权限不足、对象不存在等）时，系统 MUST 展示明确的错误信息。

**导出查询结果**

- **FR-006**: 系统 MUST 在查询结果表格中提供右键菜单项"导出为 CSV"和"导出为 JSON"。
- **FR-007**: 系统 MUST 支持将当前查询对应的完整结果集（而非仅当前视口内已渲染的行）导出到用户选择的本地文件。
- **FR-008**: 导出的 CSV MUST 包含表头行，并对包含逗号、换行、引号的字段值进行正确转义；导出的 JSON MUST 为对象数组，字段名与结果列名一致。
- **FR-009**: 系统 MUST 正确处理 NULL 值（CSV 中为空字段，JSON 中为 `null`），不得输出误导性的字符串。
- **FR-010**: 导出过程中系统 MUST 保持界面可响应，并给出进行中的状态反馈。
- **FR-011**: 导出失败时（磁盘空间不足、权限问题等）系统 MUST 提示具体错误，并不留下不完整的目标文件。

**复制行数据**

- **FR-012**: 系统 MUST 允许用户在结果表格中选择一行或多行。
- **FR-013**: 系统 MUST 提供"复制为 INSERT"、"复制为 JSON"、"复制为 CSV"三种右键菜单操作，作用于当前选中行。
- **FR-014**: "复制为 INSERT" MUST 生成语法可直接执行的 `INSERT INTO ... VALUES ...` 语句，对字符串/日期等类型正确加引号，对 NULL 使用 `NULL` 关键字。
- **FR-015**: 当结果集能确定唯一来源表时，生成的 INSERT 语句 MUST 使用该表的真实表名；当无法确定唯一来源表时，系统 MUST 生成带占位符表名的语句并提示用户核对。
- **FR-016**: 未选择任何行时，复制菜单项 MUST 被禁用或提示需先选择行。

**SQL 格式化**

- **FR-017**: 系统 MUST 在 SQL 编辑器中提供一个可通过按钮或快捷键触发的"格式化"操作。
- **FR-018**: 格式化 MUST 统一 SQL 关键字大小写、子句换行与缩进风格，且不改变语句的执行语义。
- **FR-019**: 当编辑器中存在多条以分号分隔的语句时，格式化 MUST 独立处理每条语句。
- **FR-020**: 当待格式化的 SQL 无法被解析时，系统 MUST 提示无法格式化并保留原文本不变。
- **FR-021**: 格式化操作 MUST 可通过标准撤销操作还原为格式化前的文本。

**数据导入**

- **FR-022**: 系统 MUST 支持用户选择一个已存在的目标表，并从本地选择 CSV、JSON 或 SQL 文件进行导入。
- **FR-023**: 对 CSV/JSON 导入，系统 MUST 提供文件字段到目标表列的映射步骤，并在必填列缺失映射时提示。
- **FR-024**: 对 SQL 文件导入，系统 MUST 按文件中语句的顺序执行。
- **FR-025**: 导入过程中若发生数据写入失败（约束冲突、类型不匹配等），系统 MUST 中止导入并回滚本次已写入的数据，不产生部分导入的不一致状态，同时报告失败的具体位置和原因。
- **FR-026**: 导入完成后，系统 MUST 展示成功导入的记录数（或失败摘要）。
- **FR-027**: 系统 MUST 在开始写入数据前校验所选文件非空且格式可解析，无效文件 MUST 在写入任何数据前被拒绝。

### Key Entities

- **DDL 结果（DDL Result）**：表示某个表或视图的定义语句文本，关联到具体的数据库对象（表名/视图名、所属 schema）。
- **导出任务（Export Job）**：一次查询结果导出操作，包含目标格式（CSV/JSON）、目标文件路径、结果行数、完成状态。
- **行剪贴板负载（Row Clipboard Payload）**：一次"复制行"操作生成的文本内容，包含所选格式（INSERT/JSON/CSV）、来源表（可能不确定）、涉及的行数。
- **导入任务（Import Job）**：一次数据导入操作，包含源文件（格式、路径）、目标表、列映射关系、成功/失败行数及失败详情。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户从右键表名到看到该表完整 DDL 的操作步骤不超过 2 次点击，且结果在 1 秒内显示（常规大小的表）。
- **SC-002**: 用户导出一份查询结果为 CSV 或 JSON 的操作步骤从"创建定时任务"缩短为"右键 → 选择格式 → 选择保存位置"，全程无需离开当前查询界面。
- **SC-003**: 用户复制选中行为 INSERT/JSON/CSV 后，生成的内容可直接粘贴使用（INSERT 语句可直接执行，JSON/CSV 可直接被其他工具解析），无需手工修正格式。
- **SC-004**: 用户对常见长度的 SQL 语句执行一键格式化后，语句在数据库中的执行结果与格式化前完全一致（0 处语义偏差）。
- **SC-005**: 用户能够将一个结构匹配的中等规模数据文件（数千行级别）导入到已存在的表中并获得准确的成功/失败行数汇报，导入失败时表数据保持导入前状态（不产生部分写入）。

## Assumptions

- 导入/导出/DDL 查看/复制/格式化均面向当前已实现的数据库类型（以 PostgreSQL 为首期目标），后续新增数据库类型时复用同一套用户交互。
- 数据导入的目标表必须已存在；本功能范围内不包含"根据导入文件自动创建新表"的能力（如需新表，用户先手动创建后再导入）。
- 查询结果导出针对的是"当前查询已产生的完整结果集"，不是重新对数据库发起一次新的、无限制的全表扫描；若结果集本身有行数上限（如受限的查询），导出遵循同样的行数范围。
- SQL 格式化基于通用 SQL 语法风格进行排版，不需要支持数据库特有的过程式语法（存储过程、触发器体）的深度美化；遇到无法解析的语法时保底策略是不改动原文本。
- 复制为 INSERT 在无法唯一确定来源表时生成的占位符语句仅供用户手工替换表名后使用，不视为功能缺陷。
- 导入/导出操作均在用户已建立的数据库连接权限范围内执行，不额外提升或绕过数据库本身的权限控制。
