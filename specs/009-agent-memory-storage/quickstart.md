# Quickstart 验证指南: AI Agent 多轮对话与本地记忆化存储

本文件提供功能实现后的手动验证步骤。所有操作在开发环境（`pnpm run dev`）下执行，无需额外测试框架。

## 前置条件

1. 项目启动：`pnpm run dev`
2. DeepSeek API 密钥已在 `.env` 中配置（`DEEPSEEK_API_KEY=sk-...`）
3. 至少有一个已连接的数据库（用于测试 Agent 的数据库相关工具调用）

---

## 验证场景

### V1: 基本多轮对话（对应 User Story 1）

**目的**: 验证 Agent 能在同一对话中记住前文

**步骤**:

1. 切换到 **Code 模式**（点击左侧侧边栏的 Code 图标）
2. 在左侧面板确认"对话历史"面板存在（替换了原有的"任务列表-示例项目"）
3. 点击"新建对话"按钮（位于 actions 组或面板 headerActions）
4. 在 Code 模式输入框中输入：`帮我查一下当前数据库有哪些表`
5. 等待 Agent 返回结果
6. 在同一对话框中输入：`刚才列出的第一张表有哪些字段？`
7. **预期**：Agent 能正确理解"刚才列出的第一张表"指的是第 4 步返回结果中的第一张表，并查询其字段信息，**无需用户再次指定表名**
8. 继续输入：`那第二张表呢？`
9. **预期**：Agent 理解指代并查询第二张表的字段

**通过标准**: Agent 连续 5 轮以上正确引用前文信息。

---

### V2: 对话持久化与恢复（对应 User Story 2）

**目的**: 验证对话在应用重启后不丢失

**步骤**:

1. 完成 V1 中的多轮对话（确保至少有 3 轮交互）
2. 记录当前对话的标题（左侧面板显示的首条指令截取文字）
3. 完全关闭应用（窗口关闭，确认进程已退出）
4. 重新启动应用（`pnpm run dev`）
5. 切换到 Code 模式
6. **预期**：左侧"对话历史"面板显示之前的对话，标题和更新时间和关闭前一致
7. 点击该对话
8. **预期**：加载完整的历史消息，包含之前所有轮次的用户指令和 Agent 回复
9. 输入一条新指令：`谢谢，这些信息很有用`
10. **预期**：Agent 基于前文上下文给出合理回复（而非询问"你在说什么"）

**通过标准**: 重启后对话列表正确显示、消息完整、可继续交互。

---

### V3: 对话管理操作（对应 FR-006/007/008）

**目的**: 验证对话列表的 CRUD 和归档功能

**步骤**:

1. 创建 3 条新对话（通过"新建对话"按钮）
2. 在第一条对话中输入一些内容，使其有实际消息
3. **归档**：右键点击第一条对话，选择"归档"
4. **预期**：该对话从主列表消失，出现在"已归档"子分组中
5. **取消归档**：右键点击已归档的对话，选择"取消归档"
6. **预期**：对话回到主列表
7. **删除**：右键点击第二条对话，选择"删除"，在确认对话框中确认
8. **预期**：第二条对话从列表中永久移除
9. 重启应用验证删除的对话确实不存在

**通过标准**: 归档/取消归档/删除操作按预期生效，重启后状态保持。

---

### V4: 上下文窗口裁剪（对应 FR-011）

**目的**: 验证长对话不会因超出上下文窗口而失败

**步骤**:

1. 创建一条新对话
2. 连续发送 15+ 条指令（如每次询问不同表的结构），制造长对话历史
3. 观察 Agent 的回复质量
4. **预期**：Agent 在第 10+ 轮后仍能正常响应，不会因上下文过长而报错或返回截断结果
5. **注意**：早期的上下文可能被裁剪，Agent 可能"忘记"最早的表查询，但最近的 5-8 轮交互的上下文应保持完整

**通过标准**: Agent 不因上下文过长而崩溃；近期消息的上下文完整。

---

### V5: 空状态处理（对应 FR-018）

**目的**: 验证无对话时的引导体验

**步骤**:

1. 删除所有历史对话（逐一右键删除）
2. **预期**：左侧"对话历史"面板显示引导文案"暂无对话记录，开始一段新的对话吧"和醒目的"新建对话"按钮
3. 点击"新建对话"按钮
4. **预期**：成功创建新对话并选中

**通过标准**: 空状态引导正确展示，新建按钮可正常工作。

---

### V6: Agent 执行中切换对话（对应 FR-016）

**目的**: 验证中断与恢复机制

**步骤**:

1. 确保有一个数据库连接且 Agent 已配置
2. 在对话 A 中发送一条会触发修改类工具的指令（如"帮我在 test 库中创建一个临时表"）
3. 当 Agent 弹出工具确认对话框（`paused_for_confirmation`）时，**不处理确认**，直接点击左侧另一条对话 B
4. **预期**：成功切换到对话 B，对话 A 的确认状态保持不变
5. 在对话 B 中输入一条独立指令并等待完成
6. 切回对话 A
7. **预期**：对话 A 显示之前的确认对话框仍在等待，用户可继续确认或拒绝

**通过标准**: 切换不丢失对话 A 的暂停状态，切回后可正常恢复。

---

### V7: 性能验证（对应 User Story 3）

**目的**: 验证大数据量下的性能表现

**步骤**:

1. （需预先构造或通过连续使用积累）确保至少有 50 条对话记录，部分对话包含 50+ 条消息
2. 重启应用，记录从启动到 Code 模式可交互的耗时
3. 在对话列表中快速上下滚动
4. 选择一条包含大量消息的对话，上下滚动浏览历史
5. **预期**：
   - 启动耗时与空数据状态差异不超过 2 倍
   - 对话列表滚动流畅无明显卡顿
   - 长对话浏览无延迟加载

**通过标准**: 主观感知无明显性能降级（无 1 秒以上的 UI 冻结）。

---

## 验证注意事项

- 验证过程中如发现异常，注意检查 DevTools Console（渲染进程）和主进程终端输出
- 对话数据文件位置：`{electron userData}/conversations/` 目录（可通过主进程日志确认路径）
- 如需手动清理对话数据：删除 `{userData}/conversations/` 目录并清除 `config.json` 中的 `conversations` key
