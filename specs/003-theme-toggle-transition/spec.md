# Feature Specification: 亮暗模式切换与丝滑过渡动画

**Feature Branch**: `003-theme-toggle-transition`

**Created**: 2026-08-10

**Status**: Draft

**Input**: User description: "帮我处理下亮暗模式切换的新功能：1.顶部栏的搜索按钮后添加一个亮暗模式切换的图标；2.亮暗模式要避免所有文字和图标等相关组件渲染出现颜色覆盖的问题（保证暗色模式下有很好的显示效果），不会出现颜色覆盖导致的内容消失问题；3.点击切换亮暗色的按钮后，要有丝滑的CSS样式交互，要有以该按钮位置边框为起点向四周扩散变暗色，直至窗口全部被覆盖暗色模式的动画效果，要注意渲染性能与优化"

## 特性概述

当前应用仅实现了浅色主题（见 `specs/001-app-shell-ui/spec.md` 的既有假设：本期仅浅色）。本特性为应用引入完整的亮/暗两套配色，并在顶部栏搜索按钮之后新增一个可点击的亮暗模式切换图标；点击后应用在全局范围内切换主题，并播放一个以该图标在屏幕上的位置为起点、向四周扩散直至覆盖整个窗口的视觉过渡动画。除"新增开关"本身之外，本特性还包含两项同等重要的约束：暗色模式下应用内所有文字、图标、边框等元素必须保持清晰可辨，杜绝"颜色覆盖导致内容在深色背景下看不清甚至消失"的问题；以及切换动画本身要流畅顺滑，不能因为引入动画而带来明显的渲染性能问题。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 一键切换亮暗主题 (Priority: P1)

用户在顶部栏搜索按钮旁看到一个亮暗模式切换图标，点击后应用整体（标题栏、侧边栏、结构树、内容区、对话框、SQL 编辑器等）从当前主题切换为另一主题，图标自身的视觉状态也随之改变（如太阳/月亮），再次点击可以切换回去。

**Why this priority**: 是本特性的核心交互入口，没有这个开关用户无法触发主题切换，后续"暗色模式下内容清晰可读"与"扩散动画"两项要求都建立在这个开关能够正常工作的基础之上。

**Independent Test**: 在应用任意界面点击该图标，确认标题栏、侧边栏、正文区域的颜色整体切换为对应主题的配色；再次点击验证能够切换回来。

**Acceptance Scenarios**:

1. **Given** 应用当前处于浅色模式，**When** 用户点击切换图标，**Then** 应用整体切换为暗色模式，图标状态相应改变
2. **Given** 应用当前处于暗色模式，**When** 用户点击切换图标，**Then** 应用整体切换回浅色模式
3. **Given** 用户切换主题后关闭并重新启动应用，**When** 应用重新加载，**Then** 应用保持用户上次选择的主题，而不是每次都回退到默认浅色

---

### User Story 2 - 暗色模式下内容清晰可读，无颜色覆盖导致的"消失" (Priority: P1)

用户在暗色模式下浏览应用的任意界面（顶部栏、侧边栏结构树、连接状态徽章、按钮、表单、对话框、SQL 编辑器及其语法高亮等），所有文字、图标、边框在深色背景下都具备足够对比度，不会出现"深色文字/图标叠加在深色背景上而看不清或完全消失"的情况。

**Why this priority**: 这是用户明确提出的强约束——避免颜色覆盖导致内容消失，直接决定暗色模式是否真正可用；若这一条不满足，开关本身没有意义，因此与 Story 1 同为最高优先级。

**Independent Test**: 切换到暗色模式后，逐一走查应用当前已有的每类界面/组件（结构树各级节点、连接状态徽章、按钮 hover/disabled 态、输入框、下拉菜单、设置面板、SQL 编辑器），确认每一处文字与图标都清晰可辨，不存在任何文字/图标颜色与其直接背景色相同或接近而导致不可读的情况。

**Acceptance Scenarios**:

1. **Given** 应用处于暗色模式，**When** 用户查看侧边栏结构树的服务器/数据库/表节点文字与状态徽章，**Then** 所有文字、图标、徽章文案在深色背景下清晰可辨，对比度达到常规可读性标准
2. **Given** 应用处于暗色模式，**When** 用户打开设置面板、连接表单、下拉菜单等浮层组件，**Then** 浮层自身背景随主题切换为深色，其中的文字与图标同样清晰可辨，不出现"浮层仍是浅色底配深色主题图标"或反之的不匹配组合
3. **Given** 应用处于暗色模式，**When** 用户打开 SQL 编辑器，**Then** 编辑器的背景、文字与语法高亮同步切换为适合深色背景的配色方案，不出现深色文字在深色编辑器背景上无法辨认的情况
4. **Given** 某个组件此前的样式固定为某一主题的配色（未随主题联动），**When** 该组件在暗色模式下渲染，**Then** 该组件必须被纳入本次改造范围一并修正，不允许遗留任何未适配暗色模式的组件

---

### User Story 3 - 从按钮位置向外扩散的丝滑切换动画 (Priority: P2)

用户点击切换图标的瞬间，能看到一个从按钮所在位置开始、向四周扩散直至覆盖整个窗口的过渡动效，扩散完成后新主题的颜色完全铺满窗口；整个过程流畅无卡顿，帧率稳定。

**Why this priority**: 是明确的体验加分项，建立在 Story 1（开关能切换）与 Story 2（切换后颜色本身正确、可读）之上——没有这个动画，主题切换依然是完整可用的功能，因此优先级低于前两者。

**Independent Test**: 点击切换图标，观察扩散动画是否以图标所在位置为起点、平滑扩散覆盖全窗口；在窗口尺寸变化（如最大化/还原）或连续快速点击时验证不出现撕裂、卡顿或残留的中间态色块。

**Acceptance Scenarios**:

1. **Given** 用户点击切换图标，**When** 动画开始播放，**Then** 扩散效果从图标所在的屏幕位置为起点，覆盖范围随时间平滑增长直至覆盖窗口最远角
2. **Given** 动画正在播放，**When** 用户在动画尚未结束时再次点击切换图标，**Then** 系统能够合理处理该次点击（如中断旧动画并以新状态重新播放，或在动画结束前忽略重复点击），不出现界面撕裂、主题状态错乱或动画堆积卡死
3. **Given** 用户的系统开启了"减弱动态效果"一类无障碍设置，**When** 用户切换主题，**Then** 系统直接完成主题切换并跳过扩散动画，避免引起不适
4. **Given** 窗口尺寸发生变化（拖拽调整/最大化/还原），**When** 用户随后触发主题切换，**Then** 扩散动画的覆盖范围仍正确适配当前窗口的实际尺寸，不出现覆盖不全或超出窗口的情况

---

### Edge Cases

- 用户在动画播放期间快速调整窗口大小会怎样？
- 应用刚启动、主题尚未从上次记忆的偏好恢复完成前，是否会短暂闪烁默认主题（FOUC），如何避免？
- 无法使用鼠标定位动画起点的键盘/屏幕阅读器用户，如何感知并操作这个切换图标？
- 应用内嵌的第三方渲染内容（如 SQL 编辑器自带的语法高亮引擎）若有独立的主题机制，如何与全局主题保持同步，避免出现两套主题不一致的"半明半暗"画面？

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须在顶部栏搜索按钮之后新增一个亮暗模式切换图标/按钮，点击可在浅色与暗色两种主题之间切换
- **FR-002**: 系统必须将当前主题状态实时同步给应用内全部界面区域（标题栏、侧边栏、结构树、工作区内容、对话框/浮层、SQL 编辑器及语法高亮），确保切换后不存在仍停留在旧主题配色的区域
- **FR-003**: 系统必须保证暗色模式下，应用内任意文字、图标与其所在的直接背景之间保持足够对比度，不出现文字/图标颜色与背景色相同或过于接近导致内容不可辨认的情况
- **FR-004**: 系统必须记住用户上次选择的主题，并在应用下次启动时自动以该主题呈现，无需用户每次重新切换
- **FR-005**: 系统必须在用户点击切换图标时，播放一个以该图标在屏幕上的位置为起点、向四周扩散直至覆盖整个应用窗口的视觉过渡效果，动画结束后新主题完全生效
- **FR-006**: 系统必须保证该切换动画在正常使用场景下流畅播放，不出现明显掉帧、卡顿或残留的中间态色块
- **FR-007**: 系统必须在操作系统或用户开启"减弱动态效果"等无障碍偏好时，跳过扩散动画、直接完成主题切换
- **FR-008**: 系统必须防止用户连续快速点击切换图标时出现界面撕裂、主题状态错乱或动画堆积卡死的情况
- **FR-009**: 切换图标本身必须能清楚指示当前所处的主题及点击后将切换到的主题（例如图标随主题变化）
- **FR-010**: 该切换图标必须可通过键盘等非鼠标方式聚焦并激活，并提供可被屏幕阅读器识别的文本说明

### Key Entities

- **主题偏好设置**：代表用户当前选择的主题模式（浅色/暗色）及其持久化记录，供应用启动时读取以恢复上次外观

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户在应用任意界面点击切换图标后，1 秒内应用全部界面区域（无遗漏组件）完成主题切换
- **SC-002**: 在暗色模式下随机抽查应用内不少于 20 处文字/图标元素，100% 具备可辨识的对比度，不存在因颜色覆盖导致内容看不清或消失的情况
- **SC-003**: 主题切换动画在标准桌面硬件上播放期间，用户感知不到明显卡顿，动画过程保持视觉连续、无跳帧感
- **SC-004**: 用户切换主题后关闭并重新打开应用，100% 的情况下应用以用户上次选择的主题呈现，而非默认回退到浅色
- **SC-005**: 开启系统级"减弱动态效果"偏好的用户切换主题时，100% 不会看到扩散动画，仅看到主题的直接切换

## Assumptions

- 本特性只提供"浅色/暗色"二态手动切换，不引入"跟随系统主题"的第三种模式；应用启动时默认沿用用户上次的手动选择，首次安装、尚无历史记录时默认浅色（与现状一致）
- 主题偏好属于本机/本用户级别的界面设置，与具体数据库连接、工作区内容无关，其持久化范围与既有的其他界面偏好设置（如侧边栏折叠状态）保持一致的存储方式
- SQL 编辑器（Monaco）等带有自身独立主题机制的内嵌组件，视为需要随全局主题联动切换的对象，纳入"所有相关组件"的范围
- 扩散动画是纯视觉过渡效果，不承载额外交互逻辑；动画播放期间不阻塞用户的正常输入操作
- 暗色模式的具体配色数值以保证可读性与常规可用性为目标，不要求逐像素还原某个特定设计规范
