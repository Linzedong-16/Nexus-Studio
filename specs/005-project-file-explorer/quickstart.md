# Quickstart：顶部项目选择器与 VSCode 风格文件资源管理器

本指南用于手动验证本功能端到端可用（本仓库当前无自动化测试框架，遵循宪法"自测验证"流程）。

## 前置条件

- 已安装依赖：`pnpm install`
- 准备一个本地测试文件夹，建议结构：

  ```text
  test-project/
  ├── .git/                 # 隐藏文件夹，用于验证隐藏项过滤
  ├── src/
  │   ├── index.ts
  │   └── utils/
  │       └── helper.ts
  ├── docs/
  │   └── readme.md
  ├── query.sql
  ├── data.json
  └── logo.png               # 二进制文件，用于验证二进制探测
  ```

## 启动

```bash
pnpm dev
```

## 验证场景（对应 spec User Story 1-4）

### 场景 1：顶部入口打开/切换项目（User Story 1）

1. 应用启动后未打开任何项目，确认顶部导航出现"选择项目"占位入口，且左侧侧边栏不显示任何文件资源管理器面板。
2. 点击该入口，确认下拉菜单出现「打开文件夹」与「最近」分组（首次为空）。
3. 选择「打开文件夹」，选中 `test-project`，确认：顶部入口文案变为 `test-project`；左侧出现该文件夹的文件树；再次打开下拉菜单，「最近」列表顶部出现 `test-project`。
4. 重启应用（`Ctrl+C` 后重新 `pnpm dev`），点击顶部入口，确认「最近」列表仍包含 `test-project`（验证持久化，SC-002）。
5. 准备第二个测试文件夹并打开，再通过「最近」列表点击回 `test-project`，确认无需再次弹出系统目录选择器即可切换（FR-006）。

### 场景 2：浏览文件树（User Story 2）

1. 确认根节点以可折叠标题形式展示 `test-project`，其下 `src`、`docs` 目录排在 `query.sql`/`data.json`/`logo.png` 等文件之前。
2. 确认 `.git` 隐藏文件夹不出现在树中任何层级（FR-009）。
3. 逐级展开 `src` → `utils`，确认 `helper.ts` 正确显示，且展开 `docs` 不影响 `src` 的展开状态（FR-011）。
4. 点击根节点标题整体折叠，确认全部内容隐藏；再次点击展开，确认 `src`/`utils` 此前的展开状态被保留（FR-010）。
5. 切换到另一个「最近」项目，确认树被新项目结构完全替换，无残留旧节点/展开状态（FR-012）。

### 场景 3：文件/文件夹管理操作（User Story 3）

1. 在根目录空白处右键，选择「新建文件」，输入 `notes.txt`，确认文件创建在根目录并进入命名可编辑态；重复用同名再新建一次，确认系统提示命名冲突并阻止创建（FR-013/019）。
2. 在 `src` 文件夹上右键新建文件夹 `components`，确认创建在 `src` 内部而非根目录（FR-013）。
3. 选中 `notes.txt`，触发重命名（右键菜单或快捷键），改名为 `notes-renamed.txt`，确认磁盘文件名同步更新（FR-014）。
4. 选中 `notes-renamed.txt`，触发删除，确认弹出确认提示；确认后检查系统回收站中出现该文件（FR-015/024）。
5. 在 `data.json` 上右键「复制路径」，粘贴到任意文本框验证是绝对路径；再「复制相对路径」，验证结果是相对于 `test-project` 根目录的路径（FR-016）。
6. 将 `helper.ts` 拖拽到 `docs` 文件夹上释放，确认文件被移动到 `docs` 内部，`src/utils` 下不再显示该文件（FR-017）。
7. 尝试将 `src` 文件夹拖拽到其子文件夹 `utils` 上，确认操作被拒绝、目录结构无变化（FR-017 边界）。

### 场景 4：任意非二进制文件预览/编辑（User Story 4）

1. 点击 `query.sql`，确认在新标签页中打开且保留原有 SQL 高亮与执行能力。
2. 点击 `data.json`，确认新标签页展示 JSON 内容并有对应语法高亮（FR-020）。
3. 再次点击已打开的 `data.json`，确认复用已存在标签页而非新开一个（FR-020）。
4. 点击 `logo.png`，确认系统提示"不支持预览"，且未新增任何标签页（FR-021）。
5. 在 `data.json` 标签页中修改内容并保存，确认磁盘文件内容同步更新（FR-022）。
6. 切换到另一个「最近」项目，确认 `query.sql`/`data.json` 对应的标签页被自动关闭，工作区不残留旧项目的文件标签页（FR-025）。
7. 重新打开 `test-project`，打开 `notes.txt`（若已在场景 3 中重命名/删除则改用其他现存文件），对其执行重命名，确认对应标签页自动更新为新路径与新标题；对其执行删除，确认对应标签页自动关闭（FR-026）。

## 通过标准

以上全部步骤按预期结果执行，且未观察到：控制台报错、界面卡死（尤其是大目录展开场景）、旧项目残留标签页或树节点。全部通过后可认为本功能实现满足 spec 的验收标准（SC-001 ~ SC-006）。
