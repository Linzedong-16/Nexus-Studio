# Feature Specification: 顶部项目选择器与 VSCode 风格文件资源管理器

**Feature Branch**: `005-project-file-explorer`

**Created**: 2026-08-12

**Status**: Draft

**Input**: User description: "查看更改代码目前实现了文件资源管理器功能不要在侧边栏打开了，在顶部导航添加一个"选择项目"的顶部栏，如图类似Trae的该功能，交互逻辑：1. 点击该栏，弹出下拉菜单，出现打开文件夹（目前只考虑这个）下方是最近添加的所有记录的文件夹（直记录最近使用的20个即可）；2. 打开文件夹或点击最近使用的项目后，把文件夹下所有除隐藏文件的文件渲染到目前的左侧文件资源管理器；3. 这些文件夹可还有子文件夹以及其他等等，参考vscode一样把他们全部渲染出来，文件树结构的，并且要求可以展开折叠文件资源股那里其下方再套一层"文件"，参考vscode，可以把该根目录的所有文件都折叠和展开如图二； 4.像vscode一样对项目操作 新增文件夹、文件、在别的目录下新建文件夹文件，文件夹和文件还能被选择，包括文件拖拽编排、删除、重命名及其快捷键、复制路径、复制相对路径 都可以做到，部分功能要店家右键菜单； 5.最后是，对于任意文件，除了二进制的都应该可以被点击打开新增一个tab页渲染出来，目前渲染的逻辑参考原生无插件的vscode"

## Clarifications

### Session 2026-08-12

- Q: 用户删除文件/文件夹时，系统应该移入系统回收站（可恢复）还是直接永久删除（不可恢复）？ → A: 移入系统回收站（可恢复）。
- Q: 当用户切换到「最近」列表中的另一个项目时，是否应保留当前已打开的、属于旧项目的文件标签页？ → A: 不保留——切换项目时自动关闭旧项目下所有已打开的文件标签页。
- Q: 当用户对某个正在标签页中打开的文件执行重命名或删除时，对应的已打开标签页应如何处理？ → A: 自动跟随更新/关闭——重命名时标签页自动更新为新路径与新标题，删除时标签页自动关闭。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 通过顶部导航选择/切换项目文件夹 (Priority: P1)

用户在顶部导航看到一个"选择项目"入口（未打开任何文件夹时显示占位文案，已打开文件夹时显示当前项目名称）。点击该入口弹出下拉菜单，菜单顶部是「打开文件夹」操作，下方是最近使用过的文件夹列表（最多 20 条，按最近使用时间排序，当前激活的项目有明显标记）。用户点击「打开文件夹」唤起系统目录选择器选中一个文件夹，或直接点击最近列表中的一项，该文件夹即成为当前激活的项目根目录。

**Why this priority**: 这是本功能的入口——如果用户无法方便地选择/切换项目文件夹，后续的文件树浏览、文件操作、文件预览都无从谈起，也是当前"文件资源管理器塞进侧边栏"这一问题的直接替代方案。

**Independent Test**: 点击顶部"选择项目"入口，验证下拉菜单弹出且包含「打开文件夹」和「最近」两个区域；选择一个本地文件夹后验证顶部入口文案更新为该文件夹名称，且左侧文件资源管理器开始渲染该文件夹内容；重新点击顶部入口，验证刚打开的文件夹已出现在「最近」列表顶部。

**Acceptance Scenarios**:

1. **Given** 应用尚未打开任何项目文件夹，**When** 用户查看顶部导航，**Then** 顶部显示一个"选择项目"占位入口，且左侧全局侧边栏中不再包含文件资源管理器面板。
2. **Given** 用户点击顶部"选择项目"入口，**When** 下拉菜单弹出，**Then** 菜单中包含「打开文件夹」操作，其下方是「最近」分组，展示最多 20 条最近使用过的文件夹（若从未打开过任何文件夹则该分组为空或不展示）。
3. **Given** 下拉菜单已打开，**When** 用户点击「打开文件夹」并在系统目录选择器中选中一个文件夹，**Then** 该文件夹成为当前激活项目，下拉菜单关闭，顶部入口文案更新为该文件夹名称，左侧文件资源管理器开始渲染该文件夹的内容。
4. **Given** 「最近」列表中已有至少一条记录，**When** 用户点击其中一条，**Then** 该文件夹立即成为当前激活项目（无需再次弹出系统目录选择器），左侧文件资源管理器渲染其内容。
5. **Given** 用户已经打开了 20 个不同的文件夹作为项目，**When** 用户打开第 21 个不同的文件夹，**Then** 「最近」列表中最久未使用的一条被移除，列表始终保持不超过 20 条。
6. **Given** 某个文件夹已经在「最近」列表中，**When** 用户再次打开同一个文件夹（无论通过「打开文件夹」重新选择还是点击该「最近」项），**Then** 列表中不出现重复项，该项被移动到列表最前面并更新为最新使用时间。
7. **Given** 应用重启，**When** 用户点击顶部"选择项目"入口，**Then** 「最近」列表中的记录与重启前一致（跨重启持久化）。

### User Story 2 - 浏览完整的项目文件树（VSCode 风格展开/折叠） (Priority: P1)

项目文件夹被激活后，用户在左侧文件资源管理器中看到该文件夹下的完整目录结构（不含隐藏文件/文件夹），文件树以根节点（项目文件夹本身）作为一个可整体折叠/展开的分组标题，其下再逐级展示子文件夹与文件，每一级子文件夹都可以独立展开/折叠，效果与原生 VSCode 资源管理器一致。

**Why this priority**: 这是文件资源管理器的核心可见价值——没有可浏览、可折叠的完整目录树，用户就无法定位到自己想要查看或操作的文件，与 User Story 1 共同构成最小可用版本。

**Independent Test**: 打开一个包含多层子文件夹的本地文件夹，验证根节点以一个可折叠的分组标题形式展示；点击根节点标题验证整个树可以被整体折叠和重新展开；逐级展开子文件夹验证每一级都能独立展开/折叠且展示正确的子项，隐藏文件/文件夹不出现在树中。

**Acceptance Scenarios**:

1. **Given** 一个项目文件夹已被激活，**When** 左侧文件资源管理器渲染完成，**Then** 树的最顶层是一个代表项目根目录的可折叠分组标题，其下方是该目录的直接子项（文件夹在前，文件在后）。
2. **Given** 根分组标题处于展开状态，**When** 用户点击该标题，**Then** 其下所有内容（包括已展开的子文件夹）整体折叠隐藏；再次点击则恢复展开，且子文件夹此前各自的展开/折叠状态被保留。
3. **Given** 树中存在尚未展开的子文件夹，**When** 用户点击该子文件夹，**Then** 系统展示其直接子项（文件夹和文件），且该展开动作不影响树中其他文件夹的展开状态。
4. **Given** 项目文件夹或其任意子文件夹中存在隐藏文件/文件夹（以 `.` 开头等系统隐藏约定），**When** 树渲染完成，**Then** 这些隐藏项不出现在文件树的任何层级中。
5. **Given** 用户在树中展开了若干层级后，切换到「最近」列表中的另一个项目，**When** 新项目的树加载完成，**Then** 树被新项目的目录结构完全替换，不残留旧项目的节点或展开状态。

### User Story 3 - 对文件/文件夹进行 VSCode 风格的管理操作 (Priority: P2)

用户可以在文件树的任意位置（根目录空白处、某个文件夹上、某个文件上）通过右键菜单和/或键盘快捷键完成：新建文件、新建文件夹（可在根目录或任意子目录下创建）、重命名、删除、复制路径、复制相对路径，以及通过拖拽将文件/文件夹移动到另一个文件夹下——交互方式与原生 VSCode 资源管理器一致。

**Why this priority**: 在能浏览项目文件树（User Story 1/2）之后，用户下一步的核心诉求是"像在 VSCode 里一样管理这些文件"，这是本功能相较"只读浏览"的核心增量价值，但不是浏览功能本身的前提，因此排在 P2。

**Independent Test**: 在文件树的根目录空白处右键，验证出现「新建文件」「新建文件夹」选项并可成功创建；在已有文件/文件夹上右键，验证出现重命名、删除、复制路径、复制相对路径等选项且均可正确执行；选中一个文件后使用重命名/删除快捷键验证生效；将一个文件拖拽到另一个文件夹上验证文件被移动。

**Acceptance Scenarios**:

1. **Given** 用户在文件树的空白区域或根目录上右键，**When** 右键菜单弹出，**Then** 菜单包含「新建文件」和「新建文件夹」，选择后在项目根目录下创建对应的新文件/新文件夹，并进入命名状态供用户输入名称。
2. **Given** 用户在某个子文件夹节点上右键，**When** 选择「新建文件」或「新建文件夹」，**Then** 新文件/新文件夹被创建在该子文件夹内部，而不是项目根目录。
3. **Given** 用户已选中树中的一个文件或文件夹，**When** 用户触发重命名（右键菜单「重命名」或对应快捷键），**Then** 该节点名称进入可编辑状态，确认后文件系统中的实际名称随之更新，树中显示新名称；若该文件当前正在某个标签页中打开，该标签页会自动更新为新的文件路径与新标题，无需用户手动关闭重开。
4. **Given** 用户已选中树中的一个文件或文件夹，**When** 用户触发删除（右键菜单「删除」或对应快捷键），**Then** 系统在执行前给出确认提示，确认后该文件/文件夹被移入系统回收站/垃圾桶（可恢复），并从文件树中移除；若该文件当前正在某个标签页中打开，该标签页会自动关闭。
5. **Given** 用户在某个文件或文件夹上右键，**When** 选择「复制路径」，**Then** 该节点的绝对路径被复制到系统剪贴板。
6. **Given** 用户在某个文件或文件夹上右键，**When** 选择「复制相对路径」，**Then** 该节点相对于当前项目根目录的相对路径被复制到系统剪贴板。
7. **Given** 用户按住一个文件节点并将其拖拽到另一个文件夹节点上方释放，**When** 释放鼠标，**Then** 该文件被移动到目标文件夹内部，原位置不再展示该文件，树自动刷新反映最新结构。
8. **Given** 用户尝试将一个文件夹拖拽到它自身或它的某个子文件夹上，**When** 释放鼠标，**Then** 系统拒绝该操作并不做任何改动（避免形成非法的目录嵌套）。
9. **Given** 用户尝试新建一个与同目录下已有文件/文件夹同名的文件/文件夹，**When** 用户提交命名，**Then** 系统提示名称冲突并阻止创建，直到用户输入一个不冲突的名称。

### User Story 4 - 点击任意非二进制文件在新标签页中查看/编辑 (Priority: P2)

用户在文件树中点击任意一个非二进制文件（不限于 `.sql`，包括各类文本/代码文件），系统在工作区新增一个标签页展示该文件内容，渲染方式与原生（无插件）VSCode 打开文件的效果一致；若同一文件已经在某个标签页中打开，则复用该标签页而不是新开一个。对于二进制文件，点击时系统给出明确提示而不会尝试渲染乱码内容。

**Why this priority**: 这是当前实现中已经存在但被限定为"仅 `.sql` 文件"的能力的泛化——让文件资源管理器从"只能浏览/操作文件"升级为"可以直接查看任意文件内容"，是完整替代 VSCode 资源管理器体验的最后一环，依赖前三个用户故事已经建立的文件树和文件身份识别能力。

**Independent Test**: 打开一个既包含 `.sql` 文件又包含其他文本文件（如 `.md`、`.json`、`.ts`）以及至少一个二进制文件（如图片）的项目文件夹；分别点击这些文件，验证文本类文件均能在新标签页中正确显示内容，二进制文件点击后给出不支持预览的提示而不是打开空白/乱码标签页；再次点击已打开的文本文件验证复用已有标签页。

**Acceptance Scenarios**:

1. **Given** 文件树中的一个非二进制文件尚未在任何标签页中打开，**When** 用户点击该文件，**Then** 系统新增一个工作区标签页，加载并展示该文件的完整内容。
2. **Given** 某个非二进制文件已经在一个标签页中打开，**When** 用户再次点击该文件，**Then** 系统切换到已存在的标签页，而不是新建重复标签页。
3. **Given** 用户点击一个二进制文件（如图片、可执行文件等），**When** 系统识别该文件为二进制，**Then** 系统不会新开标签页尝试渲染其内容，而是提示用户该文件不支持预览。
4. **Given** 用户在文件标签页中修改了内容并保存，**When** 保存完成，**Then** 修改内容被写回磁盘上的原文件，且该行为对任意受支持的文件类型（不仅是 `.sql`）都一致有效。
5. **Given** 用户打开的文件所属项目在「最近」列表中被切换为另一个项目，**When** 项目切换完成，**Then** 该文件所属的（旧项目的）文件标签页会被自动关闭，工作区中不再残留属于旧项目的文件标签页。

### Edge Cases

- 「最近」列表中的某个文件夹路径在被再次选中时已经不存在（被移动/删除/改名）：系统应提示该路径不可用，并将其从「最近」列表中移除，而不是渲染一个空/报错的文件树。
- 项目根目录本身为空文件夹：文件资源管理器应展示"文件夹为空"的引导态，而不是长期停留在加载中。
- 用户在包含数千个文件的超大文件夹上执行「新建/展开」等操作：树应保持可用的响应速度（依赖已有的按需加载子节点机制），不应一次性渲染整棵树导致界面卡死。
- 用户对当前正在某个标签页中打开且已被修改（未保存）的文件执行「重命名」或「删除」：重命名会使标签页自动跟随更新为新路径与新标题（未保存的修改内容保留在标签页中，尚未写回磁盘）；删除会使该标签页自动关闭，未保存的修改内容随之丢失（用户可从系统回收站恢复文件本身，但无法恢复标签页中尚未保存的编辑内容）。
- 用户对同一批文件/文件夹的重命名/删除操作产生的名称，与树中另一个层级（非同目录）的同名文件/文件夹并不冲突（冲突判断仅限同一目录内）。
- 用户尝试拖拽文件到项目根目录之外（例如拖到浏览器/系统桌面之外的无效区域）：系统应忽略该次拖拽，不产生任何文件系统变更。
- 用户连续快速切换多个「最近」项目：每次切换都应中止/替换上一次尚未完成的文件树加载，避免出现新旧项目内容混合展示的竞态问题。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 顶部导航必须提供一个持久可见的"选择项目"入口；未打开任何项目文件夹时显示占位文案，已打开项目文件夹时显示当前项目（文件夹）名称。
- **FR-002**: 系统必须移除当前嵌入在全局左侧导航侧边栏中的文件资源管理器面板；文件资源管理器只能通过本功能新增的顶部入口触发展示，不再作为侧边栏的常驻区域。
- **FR-003**: 点击顶部"选择项目"入口必须弹出下拉菜单，菜单内容依次为「打开文件夹」操作、以及「最近」分组（展示最近使用过的项目文件夹）。
- **FR-004**: 「打开文件夹」操作必须唤起系统原生目录选择器；用户选中一个文件夹后，该文件夹成为当前激活项目。
- **FR-005**: 系统必须维护一份按最近使用时间排序、去重、最多保留 20 条的项目文件夹历史记录（「最近」列表），该记录必须跨应用重启持久保留。
- **FR-006**: 点击「最近」列表中的任意一条记录，必须直接将对应文件夹设为当前激活项目，且不再重新弹出系统目录选择器。
- **FR-007**: 「最近」列表中的每一条记录必须同时展示项目名称与完整路径，并对当前激活的项目给出明显区分标记。
- **FR-008**: 当「最近」列表中的记录所指向的文件夹路径在被选中时已不存在或不可访问，系统必须提示错误并将该记录从列表中移除。
- **FR-009**: 项目文件夹被激活后，左侧文件资源管理器必须递归渲染该文件夹下的完整目录结构（子文件夹与文件），并排除所有隐藏文件与隐藏文件夹。
- **FR-010**: 文件树的根节点必须以一个可整体折叠/展开的分组标题形式呈现，标题展示项目（根目录）名称；折叠时隐藏其下全部内容，展开时恢复此前各子文件夹的展开状态。
- **FR-011**: 文件树中的每一级子文件夹必须可以独立展开/折叠，子文件夹的内容可以按需加载。
- **FR-012**: 切换当前激活项目（无论通过「打开文件夹」或「最近」列表）必须用新项目的目录结构完全替换文件树，不得残留前一个项目的节点或展开状态。
- **FR-013**: 用户必须能够在项目根目录或文件树中任意文件夹节点上，通过右键菜单发起「新建文件」和「新建文件夹」，新建的对象必须创建在触发操作所在的目录下。
- **FR-014**: 用户必须能够对文件树中已存在的文件或文件夹发起「重命名」，重命名操作必须同时支持右键菜单入口与快捷键触发，确认后文件系统中的实际名称随之更新。
- **FR-015**: 用户必须能够对文件树中已存在的文件或文件夹发起「删除」，删除操作必须同时支持右键菜单入口与快捷键触发，执行前必须给出确认提示。
- **FR-016**: 用户必须能够对文件树中的文件或文件夹发起「复制路径」（绝对路径）与「复制相对路径」（相对于当前项目根目录），结果写入系统剪贴板；这两项操作通过右键菜单提供。
- **FR-017**: 用户必须能够通过拖拽操作，将文件树中的文件或文件夹拖拽到另一个文件夹节点上以将其移动到目标文件夹内部；系统必须阻止将文件夹拖拽到其自身或其子孙目录下的非法操作。
- **FR-018**: 系统必须支持在文件树中选中单个文件或文件夹节点，选中状态需在视觉上明确区分，作为后续重命名/删除/复制路径等操作的作用目标。
- **FR-019**: 用户在同一目录下新建或重命名文件/文件夹时，若产生与该目录内已有条目同名的结果，系统必须拒绝该操作并提示名称冲突。
- **FR-020**: 用户点击文件树中的任意非二进制文件，系统必须新增（或复用已存在的同文件）工作区标签页，加载并展示该文件的完整文本内容，渲染效果对标原生（无插件）VSCode 打开文件的呈现方式。
- **FR-021**: 系统必须能够判别文件是否为二进制文件；用户点击二进制文件时，系统必须提示该文件不支持预览，且不得新开标签页尝试加载其内容。
- **FR-022**: 用户对已打开的文件标签页内容进行编辑并保存，系统必须将修改内容写回磁盘上的对应文件，该能力必须对所有受支持的文本文件类型一致生效，不得局限于特定文件扩展名。
- **FR-023**: 系统必须支持超大目录结构下的按需加载，避免一次性递归读取并渲染整个项目的全部文件，导致界面无响应。
- **FR-024**: 用户删除文件/文件夹时，系统必须将其移入操作系统回收站/垃圾桶（可恢复），而不是直接永久删除。
- **FR-025**: 当用户切换当前激活项目（通过「打开文件夹」或「最近」列表）时，系统必须自动关闭所有属于前一个项目的文件标签页，不予保留。
- **FR-026**: 当用户对某个正在标签页中打开的文件执行重命名时，系统必须自动将对应标签页更新为新的文件路径与新标题；当用户对该文件执行删除时，系统必须自动关闭对应标签页。

### Key Entities

- **项目（Project / Workspace Root）**：用户通过顶部入口选中的一个本地文件夹，作为文件资源管理器当前渲染的根目录；关键属性包括绝对路径、显示名称（文件夹名）、是否为当前激活项目。
- **最近项目记录（Recent Project Entry）**：「最近」列表中的一条历史记录，关键属性包括对应项目的路径、显示名称、最后一次被使用的时间；集合整体按使用时间排序、去重、上限 20 条。
- **文件树节点（File Tree Node）**：文件树中的一个文件或文件夹，关键属性包括名称、路径、类型（文件/文件夹）、（文件夹）子节点集合、展开/折叠状态、是否被选中。
- **文件标签页（File Tab）**：因点击某个非二进制文件而在工作区打开的一个标签页，关键属性包括对应文件路径、显示标题、当前内容、是否存在未保存修改；生命周期与所属文件绑定——文件被重命名时标签页自动更新路径与标题，文件被删除或其所属项目被切换为其他项目时标签页自动关闭。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户从未打开任何项目文件夹的状态开始，通过顶部入口完成一次「打开文件夹」并看到文件树渲染完成，全程不超过 3 次点击（不含系统目录选择器内的文件夹选择本身）。
- **SC-002**: 「最近」列表在应用重启后，与重启前相比在数量、顺序、路径上保持 100% 一致，且始终不超过 20 条。
- **SC-003**: 对于包含 5 层及以上嵌套子文件夹的项目，用户仅通过逐级展开/折叠即可在 10 秒内定位到任意指定深度的目标文件。
- **SC-004**: 文件树中提供的新建文件、新建文件夹、重命名、删除、复制路径、复制相对路径、拖拽移动等操作，在正常输入下 100% 成功执行且不破坏磁盘上其余文件/文件夹的完整性。
- **SC-005**: 项目中任意非二进制文件，点击后均能在 2 秒内于新标签页中看到完整内容；任意二进制文件点击后均能立即看到"不支持预览"提示而不会看到乱码或空白页面。
- **SC-006**: 变更上线后，全局左侧导航侧边栏中不再出现任何文件资源管理器相关的常驻入口或面板。

## Assumptions

- 「打开文件夹」目前只需要支持本地文件系统文件夹；截图中出现的「克隆 Git 仓库」「连接远程主机」暂不在本功能范围内（用户已明确说明"目前只考虑这个"）。
- 同一时间只有一个激活项目（单根工作区），选择新项目/新文件夹会替换当前文件树，而不是同时展示多个项目根（与截图中"最近"列表仅对当前一项做勾选标记的行为一致）。
- 隐藏文件/文件夹的判定沿用当前已实现的规则（以操作系统/平台惯例判定的隐藏项，如以 `.` 开头的条目），本功能不改变该判定逻辑本身。
- 文件树的单击/双击交互约定沿用当前已实现的习惯（点击文件夹切换展开折叠、点击文件触发打开），本功能仅将"点击文件即可打开"的范围从仅 `.sql` 扩展到任意非二进制文件。
- 复制路径/复制相对路径写入操作系统剪贴板，相对路径以当前激活项目的根目录为基准计算。
- 现有「新建 SQL 脚本」这一针对 `.sql` 的专用快捷创建能力，由本功能中通用的「新建文件」能力取代；用户仍可通过通用新建文件功能创建 `.sql` 文件。
- 拖拽移动仅支持在同一个已激活项目的文件树内部进行（文件夹之间互相拖拽），不涉及跨越两个不同项目根目录之间的拖拽，也不涉及从操作系统外部文件管理器拖入文件。
- 新建文件/文件夹、重命名操作中的命名输入需要满足所在操作系统对文件名的基本合法性要求（如不含路径分隔符等非法字符），具体校验规则遵循操作系统限制，本功能不额外收紧或放宽。
