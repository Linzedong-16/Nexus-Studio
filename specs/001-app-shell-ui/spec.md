## 特性概述

本特性为数据库客户端（DB Client）桌面应用搭建一套参考字节 TRAE 客户端界面风格的应用外壳（App Shell）。外壳由四个固定区域构成：顶部全局操作栏、左侧可折叠侧边栏（含 Work/Code/Design 三模式切换器与用户信息区）、以及占据最大面积的核心内容视图。三种模式各自对应一组独立的页面路由，切换模式时侧边栏菜单与内容视图同步切换。本期**仅交付界面骨架与路由逻辑**，所有页面为占位内容，不包含任何数据库连接、查询等实际业务功能——后续迭代将在此骨架上逐步填充数据库客户端的真实业务能力。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 三模式切换与独立路由 (Priority: P1)

用户打开应用后，看到 TRAE 风格的整体布局：顶部全局栏、左侧侧边栏、右侧内容区。侧边栏顶部是一个分段式的模式切换器（Work / Code / Design），带有平滑的滑动指示动画。用户点击任一模式后，侧边栏中间的菜单列表与右侧内容视图同时切换为该模式专属的页面内容，且各模式之间互不干扰。

**Why this priority**: 模式切换与独立路由是整套外壳的核心机制，也是后续所有业务功能的承载容器。没有它，侧边栏折叠、用户信息区等都失去依附的骨架。只要完成本故事，应用就具备"可运行的三工作区骨架"这一最小可用价值。

**Independent Test**: 启动应用，依次点击 Work、Code、Design 三个模式标签，验证：①切换指示器有滑动动画；②侧边栏菜单随模式变化；③内容区渲染对应模式的占位页面；④直接通过 URL/路由地址访问某模式页面可正确命中。无需任何数据库连接即可完整测试。

**Acceptance Scenarios**:

1. **Given** 应用已启动且当前处于 Work 模式，**When** 用户点击 Code 模式标签，**Then** 切换指示器平滑滑动到 Code，侧边栏菜单更新为 Code 模式的菜单组，内容区渲染 Code 模式的默认首页
2. **Given** 用户处于任一模式的某个子页面，**When** 用户切换到另一模式再切回，**Then** 路由能正确回到该模式的页面组，不出现白屏或 404
3. **Given** 应用关闭前处于 Design 模式，**When** 用户重新启动应用，**Then** 应用恢复为 Design 模式（记忆最后一次使用的模式）
4. **Given** 用户手动输入了一个不存在的路由地址，**When** 路由解析失败，**Then** 内容区回退到当前模式的默认首页，而不是空白或报错

---

### User Story 2 - 侧边栏折叠与顶部全局控件 (Priority: P2)

用户点击顶部栏最左侧的折叠按钮，侧边栏以动画方式收起为仅显示图标的窄栏（或完全收起），再次点击则展开还原。顶部栏还提供全局搜索入口、"编辑"、"帮助"两个下拉菜单；窗口右上角提供最小化、最大化/还原、关闭按钮（自定义无边框窗口）。顶部栏空白区域可拖拽移动窗口。

**Why this priority**: 折叠侧边栏与全局控件显著提升内容区可用空间与操作效率，是骨架体验完整性的关键，但不阻塞"三模式骨架可用"这一核心价值，因此为 P2。

**Independent Test**: 在任意模式下：①点击折叠按钮验证侧边栏收起/展开动画与布局自适应；②点击搜索图标验证搜索面板（占位）弹出与 Esc 关闭；③点击"编辑"/"帮助"验证下拉菜单弹出；④验证窗口控制按钮与标题栏拖拽。全部无需业务数据即可测试。

**Acceptance Scenarios**:

1. **Given** 侧边栏处于展开状态，**When** 用户点击顶部栏的折叠按钮，**Then** 侧边栏在 300ms 内以动画收起为图标窄栏，内容区平滑扩展填满剩余空间
2. **Given** 侧边栏处于折叠状态，**When** 用户再次点击折叠按钮，**Then** 侧边栏动画展开还原，菜单文字重新可见
3. **Given** 侧边栏已折叠，**When** 用户重启应用，**Then** 侧边栏保持折叠状态（折叠偏好被持久化）
4. **Given** 应用处于正常运行状态，**When** 用户点击全局搜索图标，**Then** 弹出居中的搜索面板（占位，无真实搜索逻辑），按下 Esc 或点击遮罩可关闭
5. **Given** 自定义标题栏，**When** 用户点击最大化按钮，**Then** 窗口最大化且按钮切换为还原图标；再次点击恢复原始尺寸
6. **Given** 侧边栏已折叠为图标窄栏，**When** 用户点击窄栏中的模式或菜单图标，**Then** 模式切换与页面导航仍然可用

---

### User Story 3 - 用户信息区与模式占位首页 (Priority: P3)

用户在侧边栏底部看到固定的用户信息区域：头像、用户名、套餐标识（如"免费"徽章），以及一个次级入口（参考截图中的"移动端"入口）。每个模式的内容区都有一个占位首页，参考 TRAE 的 Code 首页风格：居中的大标题、一个居中的输入框骨架（含工具栏与操作按钮占位）、以及下方的快捷操作按钮组，明确传达"该模式工作区"的身份。

**Why this priority**: 用户信息区与占位首页完善视觉还原度与品牌感，但对骨架的功能性没有阻塞影响，且用户体系后续才会接入真实账号逻辑，因此为 P3。

**Independent Test**: 启动应用目视检查侧边栏底部用户区（头像/名称/徽章/次级入口）；切换三个模式，目视检查各占位首页的标题与占位元素符合参考风格。无需登录或网络即可测试。

**Acceptance Scenarios**:

1. **Given** 应用已启动，**When** 用户查看侧边栏底部，**Then** 可见用户头像、用户名、套餐徽章与次级入口，且该区域固定在底部、不随菜单列表滚动
2. **Given** 侧边栏折叠为图标窄栏，**When** 用户查看底部，**Then** 用户区以紧凑形态（仅头像）展示且不溢出
3. **Given** 用户进入任一模式，**When** 内容区渲染该模式默认首页，**Then** 页面展示居中的模式标题与占位输入/快捷操作骨架，三个模式的首页在文案或视觉上可明确区分

---

### Edge Cases

- 窗口宽度被拖到极小（如小于 800px）时，侧边栏应自动或可折叠，内容区不被挤压到不可用的宽度；外壳设定最小窗口尺寸，低于该尺寸时窗口不可继续缩小
- 侧边栏折叠状态下切换模式，窄栏图标与内容区仍需同步正确更新
- 搜索面板打开时切换模式或点击折叠按钮，搜索面板应先关闭或保持顶层且行为一致（默认：任何导航动作关闭搜索面板）
- 路由地址指向某模式下不存在的子页面时，回退到该模式默认首页；指向不存在的模式时，回退到 Work 模式首页
- 窗口最大化状态下折叠/展开侧边栏，动画与布局自适应保持一致，不出现抖动或残留空白
- 用户头像加载失败（占位资源缺失）时，显示默认首字符占位头像，不留空白区域

## Requirements _(mandatory)_

### Functional Requirements

**整体布局**

- **FR-001**: 应用 MUST 呈现固定的三区布局：顶部全局操作栏（贯穿窗口宽度）、左侧侧边栏、右侧核心内容视图，内容视图占据剩余最大面积
- **FR-002**: 应用 MUST 采用自定义无边框窗口，顶部栏右上角提供最小化、最大化/还原、关闭三个窗口控制按钮，顶部栏空白区域 MUST 支持拖拽移动窗口
- **FR-003**: 应用 MUST 设定最小窗口尺寸，防止窗口被缩小到布局不可用
- **FR-004**: 界面整体视觉风格（配色、圆角、间距、留白、字号层级）MUST 参考 TRAE 客户端截图：浅色背景、侧边栏与内容区近色系弱分割、菜单项圆角 hover 高亮

**模式切换与路由**

- **FR-005**: 侧边栏顶部 MUST 提供分段式三模式切换组件，标签为 Work、Code（带 `</>` 图标）、Design，选中项有背景高亮且指示器在切换时以滑动动画过渡
- **FR-006**: 每种模式 MUST 对应一组独立的页面路由，切换模式时内容视图切换到目标模式的路由组，路由地址可反映当前模式与页面（可分享、可直达）
- **FR-007**: 切换模式时侧边栏中间的菜单列表 MUST 同步切换为该模式专属的菜单组（参考截图：新建任务、插件市场、自动化、模板库、任务列表分组；各模式菜单组内容允许不同，本期可为相同结构的占位菜单）
- **FR-008**: 应用 MUST 持久化用户最后使用的模式，重启后恢复；首次启动默认进入 Work 模式
- **FR-009**: 无效路由 MUST 回退：模式内无效子页面回退到该模式默认首页，无效模式回退到默认模式首页，禁止白屏
- **FR-010**: 新增某个模式的页面 MUST 只需在该模式的页面/菜单配置中登记，不允许改动外壳布局组件本身（路由与菜单由配置驱动，布局与业务解耦）

**侧边栏**

- **FR-011**: 顶部栏最左端 MUST 提供侧边栏折叠按钮，点击在"展开"与"折叠为图标窄栏"两种状态间切换，过渡动画时长不超过 300ms
- **FR-012**: 侧边栏折叠状态 MUST 被持久化，重启应用后保持
- **FR-013**: 侧边栏中间区域为模式菜单区，包含菜单项列表与"任务列表"式分组（分组标题右侧有操作图标占位）；菜单项有图标+文字，hover 有圆角高亮，折叠态仅显示图标
- **FR-014**: 侧边栏底部 MUST 固定用户信息区：头像、用户名、套餐徽章、次级入口（移动端入口占位）；折叠态收缩为仅头像；该区域不随菜单滚动
- **FR-015**: 菜单列表超出侧边栏高度时可滚动，模式切换器与用户信息区保持固定

**顶部全局控件**

- **FR-016**: 顶部栏 MUST 自左向右依次包含：侧边栏折叠按钮、全局搜索图标、"编辑(E)"菜单、"帮助(H)"菜单
- **FR-017**: 点击全局搜索图标 MUST 弹出居中的搜索面板骨架（输入框占位），支持 Esc 键与点击遮罩关闭；本期不含真实搜索逻辑
- **FR-018**: "编辑"与"帮助"菜单点击后 MUST 弹出下拉菜单骨架（菜单项为占位项，如撤销/重做/复制/粘贴、关于/快捷键等），点击菜单外区域关闭

**内容视图与占位页**

- **FR-019**: 每个模式 MUST 有一个默认首页作为内容视图的占位页，参考 TRAE Code 首页：居中模式大标题（如"Code with TRAE"风格的模式标语）、居中输入框骨架（含底部工具栏与主操作按钮占位）、下方快捷操作按钮组
- **FR-020**: 三个模式的占位首页 MUST 在标题/文案上明确区分所属模式，避免用户混淆当前所在工作区
- **FR-021**: 占位页中的所有输入框、按钮、菜单项 MUST 为纯展示骨架，不产生真实业务行为，但需有可交互的视觉反馈（hover/焦点态）

**代码组织（架构约束）**

- **FR-022**: 布局外壳组件（顶栏、侧边栏、模式切换器、内容容器）MUST 与模式页面组件分离存放，外壳组件不包含任何业务逻辑
- **FR-023**: 模式、路由、菜单的定义 MUST 集中在独立的配置/注册模块中管理，UI 组件消费配置而非硬编码，保证新增/调整模式时改动局部化
- **FR-024**: 全局 UI 状态（当前模式、侧边栏折叠态、搜索面板开关）MUST 集中管理并与组件解耦，且折叠态与当前模式需可持久化恢复
- **FR-025**: 实施本特性前 MUST 先清理脚手架自带的初始化样式与示例代码（默认全局样式、示例页面、示例组件、示例图片资源、示例状态等），确保外壳样式不受脚手架默认样式污染，界面还原度以参考截图为唯一标准

### Key Entities _(include if feature involves data)_

- **模式（Mode）**：一个工作区身份，包含唯一标识、显示名、图标、关联的路由组与侧边栏菜单组；本期固定为 Work / Code / Design 三个实例
- **页面路由（Route）**：隶属于某个模式的页面地址与对应占位页面的映射，支持模式内多级子页面
- **侧边栏菜单组（Sidebar Menu Group）**：隶属于某个模式的菜单结构，包含菜单项（图标、文案、目标路由）与分组（如"任务列表"）
- **外壳 UI 状态（Shell UI State）**：当前模式、侧边栏折叠状态、搜索面板开关状态；其中前两者需跨会话持久化
- **用户信息（User Profile，占位）**：头像、显示名、套餐标识；本期为静态占位数据，无登录逻辑

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户单次点击即可完成模式切换，切换指示动画与内容更新在 200ms 内开始响应，三个模式的页面与侧边栏菜单 100% 正确对应
- **SC-002**: 侧边栏折叠/展开动画在 300ms 内完成且全程无卡顿跳变；折叠状态与当前模式在应用重启后 100% 恢复
- **SC-003**: 外壳在无任何数据库连接、无网络的环境下可完整运行与演示，全部骨架功能（模式切换、折叠、搜索面板、菜单、窗口控制）可用
- **SC-004**: 向任一模式新增一个占位页面，仅需修改该模式的页面/菜单配置（不改动外壳布局组件），验证方式：新增页面的代码变更不触及外壳组件文件
- **SC-005**: 对照 TRAE 参考截图进行走查，三区布局、模式切换器、侧边栏菜单、用户信息区、Code 首页骨架五个视觉要点全部还原，评审者可在不看代码的情况下识别出布局来源
- **SC-006**: 无效路由场景下 100% 回退到有效页面，无白屏、无未捕获错误

## Assumptions

- 本期模式标签沿用 TRAE 的 Work / Code / Design 命名，作为占位工作区；后续迭代会将三者重定义/重命名为数据库客户端的实际工作区（如连接管理、SQL 查询、数据模型设计），本期不做业务语义绑定
- 用户信息区使用静态占位数据（示例头像、示例用户名、"免费"徽章），不包含登录、注册或账号同步逻辑
- 全局搜索、编辑/帮助菜单、菜单项点击均只弹出骨架/占位反馈，不含真实搜索、编辑命令或业务动作
- 窗口控制采用自定义无边框窗口（与参考截图一致），而非操作系统原生标题栏
- 各模式的菜单组本期允许使用相同结构的占位菜单（复刻截图中的新建任务/插件市场/自动化/模板库/任务列表），后续按模式差异化
- 目标平台为桌面端（Windows/macOS/Linux），不考虑移动端与响应式断点的窄屏适配
- 主题本期仅实现浅色主题（与截图一致），深色主题不在本期范围
- 项目脚手架（electron-vite 模板）自带的初始化样式与示例代码属于本特性的清理范围，须在铺设新外壳前移除
- 项目宪法规定的技术栈约束（Electron 三层进程隔离、React + TypeScript + Tailwind + shadcn/ui + Zustand、布局组件与业务组件分离等）作为既有工程约束遵循，不属于本规格的功能决策范围
- 本特性对应宪法中的 Phase 1（基础框架）交付物，完成后应用应可独立构建、运行
