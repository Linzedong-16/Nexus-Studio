# Feature Specification: MySQL 数据库连接支持

**Feature Branch**: `007-mysql-database-support`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "实现连接MySQL数据库的引入，保证MySQL可以目前postgre已对接的大部分功能"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 新建并连接 MySQL 数据库（Priority: P1）

用户在新建连接对话框中选择"MySQL"类型，填写主机、端口（默认 3306）、数据库、用户名、密码等信息，测试连接成功后保存，随后可在连接列表中看到该连接并成功建立连接，浏览其下的全部数据库。

**Why this priority**: 没有连接能力，后续所有功能都无从谈起，这是整个功能的地基，也是用户最迫切的需求——目前应用只能连 PostgreSQL，无法接入公司/个人已有的 MySQL 实例。

**Independent Test**: 新建一个 MySQL 类型连接，填入真实的 MySQL 实例信息，点击"测试连接"看到成功提示（含服务器版本与延迟），保存后在连接列表中双击建立连接，能看到该服务器上的数据库列表。此故事不依赖本规格中的其他能力即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户打开新建连接对话框，**When** 选择数据库类型为"MySQL"，**Then** 表单展示 MySQL 适用的连接字段，端口默认填充为 3306。
2. **Given** 用户填写了一个可访问的 MySQL 实例信息，**When** 点击"测试连接"，**Then** 系统在数据库返回后展示连接成功、服务器版本号与连接延迟。
3. **Given** 用户填写了错误的密码或不可达的主机，**When** 点击"测试连接"，**Then** 系统展示明确的失败原因，不出现无响应或崩溃。
4. **Given** 一个已保存且测试成功的 MySQL 连接，**When** 用户在连接列表中建立连接，**Then** 系统展示该账号在此 MySQL 服务器上可访问的全部数据库。

---

### User Story 2 - 浏览 MySQL 数据库结构并执行查询（Priority: P1）

用户在已连接的 MySQL 数据库下浏览表、视图及其列定义，并在 SQL 编辑器中对该数据库执行任意查询语句，查看结果集。

**Why this priority**: 浏览结构与执行查询是数据库客户端最核心的日常使用场景，与连接能力同等基础，缺一不可，因此与 User Story 1 同为最高优先级。

**Independent Test**: 连接一个包含若干表的 MySQL 数据库，在导航树中展开数据库、查看表列表与某张表的列定义（列名、类型、可空性、主键标记），随后在编辑器中执行一条 `SELECT` 语句并看到正确的结果集、字段信息、行数与耗时。可独立于其他用户故事验证。

**Acceptance Scenarios**:

1. **Given** 已连接的 MySQL 数据库中存在若干表和视图，**When** 用户在导航树中展开该数据库，**Then** 系统列出全部表与视图，并可区分二者类型。
2. **Given** 用户点击某张表，**When** 查看其列定义，**Then** 系统展示每一列的名称、数据类型、是否可空、默认值、主键标记与注释，与该表的实际结构一致。
3. **Given** 用户在编辑器中输入一条合法的查询语句并执行，**When** 查询针对 MySQL 数据库运行，**Then** 系统展示结果集（列信息、行数据）、总行数与执行耗时。
4. **Given** 用户执行了一条包含语法错误的语句，**When** 提交执行，**Then** 系统展示数据库返回的明确错误信息。

---

### User Story 3 - 查看 MySQL 对象的索引、触发器、存储过程/函数、用户权限与 DDL（Priority: P2）

用户在导航树中查看 MySQL 表的索引与触发器、数据库下的存储过程与函数列表、服务器级的用户/权限列表，并可一键查看/复制表或视图的完整 DDL 定义语句。

**Why this priority**: 这些是 PostgreSQL 连接已经具备的"对象浏览"能力，用户明确要求 MySQL 要对齐"目前 postgre 已对接的大部分功能"，此类深度浏览能力是打消用户"MySQL 是阉割版"顾虑的关键，但不影响基本可用性，故次于连接与查询。

**Independent Test**: 对一个包含索引、触发器、存储过程/函数与多个用户的 MySQL 数据库，分别查看某表的索引列表、触发器列表，数据库的存储过程/函数列表、服务器的用户/权限列表，以及某表和某视图的 DDL，验证展示内容与直接执行 `SHOW CREATE TABLE`/`SHOW CREATE VIEW`/`SHOW INDEX`/`SELECT ... FROM mysql.user` 等命令得到的信息一致。可独立于导入、ER 图、备份等能力验证。

**Acceptance Scenarios**:

1. **Given** 某 MySQL 表存在若干索引，**When** 用户查看该表的索引信息，**Then** 系统展示每个索引的名称、类型、是否唯一及包含的列，与实际索引一致。
2. **Given** 某 MySQL 表存在触发器，**When** 用户查看该表的触发器信息，**Then** 系统展示触发器名称、触发定义与启用状态。
3. **Given** 某 MySQL 数据库存在存储过程或函数，**When** 用户查看该数据库的例程列表，**Then** 系统展示每个例程的名称、参数签名、返回类型（函数）与注释。
4. **Given** 用户在导航树中右键某张表并选择"查看 DDL"，**When** 请求完成，**Then** 系统展示该表完整的建表语句，支持一键复制；对视图执行同样操作时展示完整的建视图语句。
5. **Given** MySQL 服务器上存在多个用户账号（不同的用户名@主机组合），**When** 用户查看该服务器的用户/权限列表，**Then** 系统以与 PostgreSQL 角色列表一致的界面展示每个账号的用户名、可登录主机、是否具备超级权限、是否允许登录、连接数上限等信息，与该服务器实际的用户权限配置一致。

---

### User Story 4 - 向 MySQL 表导入数据（Priority: P3）

用户将本地数据（如表格数据或一组 SQL 语句）导入到 MySQL 表中，导入过程具备整体事务性：任意一行/一条语句失败则全部回滚并提示失败位置。

**Why this priority**: 导入是高价值但非每次会话都会用到的能力，建立在"已能连接、浏览、查询"的基础之上，故优先级低于前三个故事。

**Independent Test**: 对一张已知结构的 MySQL 表，分别使用"按行导入"和"按 SQL 语句导入"两种方式导入数据，验证全部成功时数据正确写入；故意构造一行/一条语句会失败的场景，验证整体回滚且系统准确报告失败位置，不产生部分写入。

**Acceptance Scenarios**:

1. **Given** 用户准备了若干行与目标表列数匹配的数据，**When** 执行按行导入，**Then** 全部数据成功写入目标表，系统报告成功写入的行数。
2. **Given** 待导入数据中某一行的字段数与目标表列数不一致或某一行违反约束，**When** 执行导入，**Then** 系统回滚全部改动，不写入任何数据，并明确指出出错的行号与原因。
3. **Given** 用户提供一组按顺序执行的 SQL 语句，**When** 执行按 SQL 导入，**Then** 全部语句成功执行后系统报告成功语句数；若中途某条语句失败，则回滚全部改动并指出失败语句序号与原因。

---

### User Story 5 - 生成 MySQL 数据库的 ER 关系图（Priority: P3）

用户对已连接的 MySQL 数据库执行"生成 ER 图"，查看所选范围内全部表的结构及其外键关系。

**Why this priority**: ER 图是分析型功能，使用频率低于日常查询与浏览，且依赖前述基础浏览能力，故优先级较低，但用户明确要求"大部分功能"对齐，需要覆盖。

**Independent Test**: 对一个包含多张存在外键关系的表的 MySQL 数据库生成 ER 图，验证图中包含全部选定表及其列信息，且外键连线与实际外键约束一致。可独立于导入、备份能力验证。

**Acceptance Scenarios**:

1. **Given** 用户选择 MySQL 数据库中的若干个数据库/表范围，**When** 触发生成 ER 图，**Then** 系统展示这些表的结构（列名、类型、主键标记）。
2. **Given** 所选范围内的表之间存在外键约束，**When** 查看生成的 ER 图，**Then** 图中以连线准确展示每一条外键关系及其来源/目标列。
3. **Given** 所选范围内的表没有任何外键约束（例如使用不支持外键的存储引擎），**When** 查看生成的 ER 图，**Then** 系统仍展示全部表结构，仅不显示连线，不报错。

---

### User Story 6 - 备份 MySQL 数据库（Priority: P4）

用户对已连接的 MySQL 数据库执行"备份"，将其导出为本地 SQL 文件，行为与现有 PostgreSQL 备份能力一致。

**Why this priority**: 备份是相对低频的运维操作，且依赖用户本机具备额外的命令行工具，价值仍高但不影响日常使用，故优先级最低。

**Independent Test**: 对一个 MySQL 数据库触发备份，指定导出目录后验证生成了一个可用的 `.sql` 备份文件；在备份工具未安装的机器上触发备份，验证系统给出明确提示并允许手动指定工具路径。

**Acceptance Scenarios**:

1. **Given** 用户本机已具备可用的 MySQL 备份工具，**When** 用户对某 MySQL 数据库触发备份并指定导出目录，**Then** 系统在该目录下生成一个以数据库名和时间戳命名的 `.sql` 文件，并提示成功。
2. **Given** 用户本机未安装备份工具且未手动指定路径，**When** 触发备份，**Then** 系统提示未找到备份工具，并允许用户手动指定工具路径后重试。
3. **Given** 备份过程中数据库连接中断或权限不足，**When** 备份失败，**Then** 系统展示具体错误原因而不是静默失败。

---

### Edge Cases

- 用户填写的 MySQL 服务器版本较旧（如已停止官方维护的版本）导致部分系统视图字段缺失时，功能应如何降级提示，而不是整体报错？
- 表使用不支持外键的存储引擎时，索引/触发器/ER 图等功能应仍可正常展示该表自身信息，只是没有外键相关数据。
- 用户同时管理 PostgreSQL 与 MySQL 连接时，连接列表、导航树、状态栏等界面需要清晰区分两种类型，避免用户混淆当前操作的是哪种数据库。
- 导入数据时字段数量与目标表列数不一致，或数据类型不匹配导致约束冲突时，需精确报告失败行/语句，不产生部分写入。
- MySQL 特有的多语句执行（一次提交多条以 `;` 分隔的语句）与 PostgreSQL 的差异，应如何在结果展示上保持一致体验。
- 备份/导入等依赖外部命令行工具的功能，在工具版本与服务器版本不匹配时应给出可理解的错误提示。
- 用户在 MariaDB（而非官方 MySQL）实例上使用本功能时，若因信息模式或权限模型差异导致部分能力异常，应提示为已知限制，而不是表现为随机报错。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 用户必须能够新建"MySQL"类型的数据库连接，表单字段（连接名称、主机、端口、数据库、用户名、密码、SSL、连接超时、颜色标签、分组）与现有连接类型保持一致的操作体验，端口默认值为 3306。
- **FR-002**: 系统必须支持对 MySQL 连接执行"测试连接"，成功时返回服务器版本与连接延迟，失败时返回明确失败原因。
- **FR-003**: 系统必须支持列出已连接 MySQL 服务器上当前账号可访问的全部数据库。
- **FR-004**: 系统必须支持列出指定 MySQL 数据库下的全部表与视图，并可区分二者类型。
- **FR-005**: 系统必须支持查看 MySQL 表的完整列定义，包括列名、数据类型、是否可空、默认值、主键标记与注释。
- **FR-006**: 系统必须支持查看 MySQL 表的索引列表，包括索引名称、类型、是否唯一及包含的列。
- **FR-007**: 系统必须支持查看 MySQL 表的触发器列表，包括名称、定义与启用状态。
- **FR-008**: 系统必须支持查看 MySQL 数据库下的存储函数与存储过程列表，包括名称、参数签名、返回类型（函数）与注释。
- **FR-009**: 系统必须支持对 MySQL 数据库执行任意 SQL 查询语句，并展示结果集（字段信息、行数据、行数、执行耗时）与执行错误信息。
- **FR-010**: 系统必须支持查看 MySQL 表与视图的完整 DDL 定义语句，并支持一键复制。
- **FR-011**: 系统必须支持向 MySQL 表按行导入数据，导入过程具备整体事务性：任意一行失败立即整体回滚，并报告失败行号与原因。
- **FR-012**: 系统必须支持向 MySQL 数据库按顺序导入一组 SQL 语句，导入过程具备整体事务性：任意一条失败立即整体回滚，并报告失败语句序号与原因。
- **FR-013**: 系统必须支持基于 MySQL 表结构与外键关系生成 ER 关系图，无外键约束时仍展示表结构本身。
- **FR-014**: 系统必须支持将 MySQL 数据库备份导出为本地 SQL 文件；若所需备份工具未就绪，必须提示用户并允许手动指定工具路径。
- **FR-015**: 系统必须在连接列表、导航树等界面中清晰标识每个连接的数据库类型（PostgreSQL / MySQL），避免用户混淆。
- **FR-016**: 当用户对某 MySQL 数据库对象（表、视图、例程等）无权限访问或该对象不存在时，系统必须展示明确的错误提示，而不是空白页面或应用崩溃。
- **FR-017**: 系统必须支持查看 MySQL 服务器上的用户/权限列表，将"用户名@可登录主机 + GRANT 权限"映射为与 PostgreSQL 角色列表一致的展示形式，字段至少包含用户名、可登录主机、是否具备超级权限、是否允许登录、连接数上限。
- **FR-018**: 本次验证与支持范围仅覆盖 MySQL 5.7+ 与 8.0，不保证与 MariaDB 的兼容性；用户在 MariaDB 环境下遇到的问题视为已知限制，留待后续迭代单独评估。

### Key Entities

- **数据库连接（Connection）**：新增"MySQL"作为可选的数据库类型，复用现有连接实体的全部通用属性（名称、主机、端口、认证信息、SSL、分组、颜色标签等），仅默认端口与展示图标随类型不同。
- **数据库 / 表 / 视图 / 列（Database / Table / View / Column）**：MySQL 下的这些对象与现有 PostgreSQL 对应实体共享同一套展示模型（名称、类型、注释、列的类型与约束信息等）。
- **索引 / 触发器 / 例程（Index / Trigger / Routine）**：表级与库级的附加结构信息，用于对象浏览面板展示，字段含义与现有实体一致。
- **用户 / 权限（User / Privilege）**：服务器级的账号信息，字段包括用户名、可登录主机、是否超级权限、是否允许登录、连接数上限，展示形式与现有 PostgreSQL 角色实体一致。
- **ER 图数据（ER Diagram Data）**：包含所选范围内的表结构与外键关系，用于关系图渲染。
- **导入结果（Import Result）**：记录一次导入操作是否全部成功、成功数量，失败时的位置与原因。
- **备份结果（Backup Result）**：记录一次备份操作是否成功、生成文件路径，失败时的错误原因。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户能够在 2 分钟内完成一次"新建 MySQL 连接 → 测试连接成功 → 保存"的完整流程。
- **SC-002**: 已连接的 MySQL 数据库中，用户在导航树中查看到的表、视图、列、索引、触发器、存储过程/函数、用户权限信息，与直接对该数据库执行对应的 `SHOW`/`DESCRIBE` 类命令得到的结果一致（抽样人工核对，准确率 100%）。
- **SC-003**: 现有 PostgreSQL 连接已支持的核心能力（查询执行、结构浏览、DDL 查看、数据导入、ER 图生成、数据库备份、用户权限查看）在 MySQL 连接下均可完成，且用户无需查阅文档即可找到对应入口。
- **SC-004**: 对于本次范围外明确列为限制的情形（如 MariaDB 环境下的差异），系统提示清晰、不产生崩溃或无响应，用户能理解"暂不支持"而非"故障"。
- **SC-005**: 用户可在同一连接列表中同时管理 PostgreSQL 与 MySQL 连接，且能在 3 秒内通过界面区分任意一个连接的数据库类型。

## Assumptions

- MySQL 没有独立于 database 的 schema 概念；本功能中每个 MySQL 数据库同时充当其唯一的 schema，以复用现有"连接 → 数据库 → schema → 表"的三级导航结构，不改变现有 UI 层级设计。
- MySQL 连接的 SSL、连接超时、颜色标签、分组等配置项直接复用现有连接表单字段，本次不新增 MySQL 专属的连接配置项（如存储引擎、字符集选择等）。
- 存储过程/函数、触发器、索引等对象浏览能力面向 MySQL 5.7+/8.0 的标准信息模式（`information_schema`），不特别处理已停止官方维护的历史版本差异。
- 视图 DDL 通过 MySQL 原生的 `SHOW CREATE VIEW` 获取，不需要像 PostgreSQL 一样手动拼装系统目录查询。
- 本次验证范围限定为官方 MySQL 5.7+/8.0，不含 MariaDB；若后续需要支持 MariaDB，作为单独的范围扩展评估。
- 备份功能依赖用户本机已安装（或可手动指定路径的）MySQL 备份命令行工具，检测与容错行为与现有 PostgreSQL 备份能力（依赖 `pg_dump`）保持一致的用户体验。
- 本次范围不包含"新增数据库类型"以外的整体导航/UI 改版，MySQL 连接接入现有界面结构与交互模式。
